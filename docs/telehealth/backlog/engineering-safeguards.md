## 4. Enforcement behavior

The planning validator runs unconditionally. Once it detects any file under an approved telehealth implementation path or any migration/table/endpoint with the telehealth prefix, it fails unless the appropriate safeguard files and workflow commands exist. This prevents feature code from landing first and “tests later.”

The runtime workflow uses Docker PostgreSQL and deterministic synthetic data. It must not contact live identity, video, payer, pharmacy, notification or clearinghouse destinations. Production startup safety is tested separately; a local passing simulation cannot be represented as production readiness.

## 5. Evidence artifacts

Every gate emits a JSON summary containing command version, commit, environment, start/end, checks, failures and artifact checksums. CI uploads non-PHI evidence. The traceability register links requirement/story/test/evidence without storing real patient or raw vendor payload data.
