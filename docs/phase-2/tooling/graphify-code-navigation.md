## Purpose

Graphify supplies a persistent code-navigation graph for future LLM harnesses and human reviewers. It is intended to make questions such as “what calls this?”, “what is affected by this change?”, and “which components bridge these areas?” cheaper to investigate before source-level verification.

It is an aid to discovery. It is not an architecture assessment, a replacement for repository inspection or tests, or evidence that a finding is resolved. It does not change the Phase 1 baseline, the canonical finding register, recommendation status, or any gate.

## Reproducible integration

The project pins Graphify and the optional C# and PowerShell tree-sitter parsers in [`tools/graphify/package.json`](../../../tools/graphify/package.json). Install from a clean checkout with:

```powershell
npm install --prefix tools/graphify
```

The checked-in [`scripts/Update-AvenChartGraph.ps1`](../../../scripts/Update-AvenChartGraph.ps1) is the supported update interface. It first operates only on committed files, runs Graphify's local structural pass, and disables node-description and community-label enrichment. The output is therefore deterministic with respect to the scoped source and does not require an API key or an LLM provider.

## Scope and privacy boundary

The committed [`.graphifyignore`](../../../.graphifyignore) excludes documentation, synthetic data, the excluded reference frontend, public-history output, agent state, lock files, build output, dependencies, and environment files. The initial index covers the supported modern clinician/portal UI, the ASP.NET Core backend, tests, and project automation scripts.

This boundary matters because Graphify's optional semantic/corpus modes may send document or media content to an underlying model provider. They are not enabled here. Direct provider backends, semantic descriptions and labels, OCR, remote URLs, transcript/agent-stat ingestion, and store mirrors are all out of scope unless the program owner separately authorizes them.

The Graphify MCP server registered for Codex is read-only and serves only the local graph file. It cannot edit the repository, application, database, or graph. Its registration is a developer-machine setting; the reproducible project configuration remains in this repository.

## Durable artifacts and maintenance

The committed artifacts are `.graphify/graph.json`, `.graphify/GRAPH_REPORT.md`, and any deterministic flow artifact generated by the update command. Caches, runtime pointers, worktree state, assistant-mode queues, converted content, and the prebuilt Studio output remain ignored because they are machine-specific or generated from the durable graph.

Before committing refreshed graph artifacts:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Update-AvenChartGraph.ps1 -Mode PortableCheck
```

Graphify 0.17.1's direct `portable-check .graphify` also inspects ignored `manifest.json` state, which intentionally contains local absolute paths. The supported script validates a temporary directory containing only the durable artifacts above, then removes that exact temporary directory. Then inspect the graph diff alongside the source change. A graph update should normally accompany a meaningful source change, but it must not obscure the actual code review.

`graphify check-update` compares the embedded source Git hash with `HEAD`. Since the durable graph is committed in a following artifact-only commit, it will report that one commit of expected metadata distance immediately after publishing an updated graph. Treat the report's recorded source hash and the intervening diff as the freshness evidence; do not mistake that expected artifact commit for an unindexed product-code change.

## Initial-index evidence

Initial build on 2026-08-23 used:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Update-AvenChartGraph.ps1 -Mode Update
```

The requested `committed` scope contained 993 candidates: 788 input files were included and 48,934 ignored files were excluded. Graphify's local AST pass processed 772 code files and generated a 13,263,904-byte `graph.json` plus an 82,224-byte `GRAPH_REPORT.md`. The report records 6,734 nodes, 15,972 extracted edges, 307 topology clusters, and zero semantic-model input/output tokens. The graph was built at Git commit `c3a55ee`.

The checked-in C# and PowerShell parsers are present. A FHIR/external-laboratory/authorization query surfaced the API host, transport, intake repository, modern UI, and workflow-test surfaces; a `Program.cs` review-delta query returned 80 impacted nodes. These are retrieval checks, not proof of either relationship completeness or clinical, security, correctness, or test adequacy.

The index is recorded as supporting assessment navigation only; it does not create a new Phase 2 finding or change implementation authorization.
