An unattended software-engineering experiment

Can an agent rebuild a mature application?

AvenChart tests whether autonomous coding agents can completely recreate and modernize an existing product in a brand-new technology stack. OpenEMR supplies the functional benchmark; every line of AvenChart application code was produced by coding agents.

This is a functional reimplementation, not a line-by-line translation of OpenEMR. Its source was used as reference material to understand what the product does, not as code to port.

The experiment

The question behind the code.

Are autonomous coding agents now capable of understanding a mature system, one behavior slice at a time, and rebuilding it cleanly on a modern stack—fully unattended?

OpenEMR was selected because it is a robust, mature, extensively used open-source EHR and practice-management application. Its breadth, depth, and proven real-world functionality made it an ideal and demanding candidate for this experiment.

Core experimental constraint Zero human-authored application code.

Across both phases, no human wrote or edited a line of application code. During phase one, the experimenter did not inspect the code either; the human role was limited to defining the objective and directing the agents.

Why OpenEMR

A respected functional benchmark

The choice reflects OpenEMR's strength, not a criticism of it. A mature, widely adopted open-source solution offered enough real functionality to make the autonomy test meaningful.

How the source was used

Reference, not translation

The agents examined OpenEMR to identify behavior and workflows. Those functional slices became the direction for clean, new implementation work; the existing code was never translated line by line.

Two phases

One foundation, two interfaces.

The first phase pursued functional parity. The second tested whether another agent could improve the experience without replacing the working backend.

Phase 01

Functional baseline

An unattended, like-for-like rebuild.

The first agent worked through OpenEMR functionality slice by slice, creating a new ASP.NET Core API, PostgreSQL data model, and React reference interface. The experimenter neither viewed nor wrote the code. The resulting application appears functional and functionally correct, though its interface is utilitarian rather than elegant.

Phase 02

Interface modernization

A new UI by Claude Code.

Claude Code was pointed at the phase-one codebase and asked to create a more polished, modern React and TypeScript interface. This phase changed only the UI: it connects to exactly the same .NET web API and data foundation created in phase one.
