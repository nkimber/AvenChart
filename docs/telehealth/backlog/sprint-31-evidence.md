## 3. Proven boundaries

- only a current `SyntheticMedicationInformationRecorded` applicant with exact promotion, patient, registration, insurance, communication, device, inventory, medication receipt/item, safety-location, callback, practice, and facility provenance can read or record the receipt;
- only server-owned catalog keys/categories, the additional-or-unlisted signal, four mandatory acknowledgments, and explicit false consequence facts cross the route;
- the local catalog remains incomplete and unmapped, and no patient report is represented as a canonical, verified, reconciled, or confirmed-negative allergy finding;
- a successful command produces one parent, the exact bounded child set, one event, and one monotonic state transition, while any bounded contention conflict is recoverable by an unchanged exact retry; and
- applicant source, canonical allergy/medication/prescription/clinical, alert/task, patient, insurance, clinician portal, intake, eligibility, consent, acceptance, financial, request, queue, appointment, encounter, care, prescribing, claim, integration, and external-action records remain unchanged.

## 4. Evidence-gate observations

The first isolated live launch used an empty migrated schema without the shared synthetic gold dataset. Applicant creation correctly failed on the missing facility provenance. Only the exact disposable database was reseeded; the normal database was not modified.

One of eight simultaneous exact allergy commands returned a bounded 409 while the first transaction was in flight, while seven returned the immutable result. Repetition showed the same legitimate contention behavior in the preceding medication stage. Both proofs now require all simultaneous results to be either 200 or 409, at least one success, exactly one receipt/event, and a subsequent unchanged retry returning the same recorded time. This makes the evidence match the API's fail-closed optimistic-concurrency contract without weakening semantic replay.

The first full browser run lacked the API expected by pre-existing authenticated portal tests on port 5001. The new-patient allergy journeys passed, while later portal logins reported connection failure. Mapping port 5001 to the isolated Sprint 31 API resolved the environment and all 56 tests then passed; no application or assertion was changed for that rerun.

## 5. Rollback and stop evidence

- base and Development configuration remain disabled, and Production enablement remains startup-rejected;
- missing, stale, expired, cross-applicant, portal-enabled, merged, patient-drifted, canonical-insurance/medication/prescription/allergy, or provenance-incomplete state cannot record allergy information;
- immutable parent/child evidence is not destructively rolled back; correction requires a separately reviewed forward migration and workflow;
- disabling or removing the routes and panel leaves the synthetic patient shell portal-disabled and without a canonical allergy, confirmed negation, alert/task, intake completion, eligibility, request, queue, care, or prescribing capability; and
- stop conditions include reaction, type, status, severity, criticality, arbitrary substance, external code, date, note, attachment, or free text crossing the route; the catalog being represented as complete or mapped; a patient report becoming verified, reconciled, or clinically actionable; routing creating authority; canonical or downstream mutation; provenance divergence; history overwrite; or an earlier safeguard regression.
